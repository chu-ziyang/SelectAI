## 一、项目概述

### 1.1 产品定位

划词助手是一款 Windows 桌面端人工智能辅助工具。用户在任意软件中选中文字后，自动弹出悬浮窗口，提供翻译、总结、解释、查词等 AI 驱动的操作，帮助用户高效处理文字信息。

### 1.2 设计理念

- **iOS 风格**：简约、高级、有美感
- **开箱即用**：预置常用动作，无需复杂配置
- **灵活可扩展**：支持自定义动作、多厂商模型
- **尊重隐私**：API Key 加密本地存储，不上传任何数据到第三方

### 1.3 核心工作流程

```
用户选中文字 → 自动弹出悬浮窗口 → 点击操作按钮 → 调用AI模型 → 结果展示 → 点击空白处消失
```

### 1.4 目标用户

| 用户类型 | 典型需求 | 关键痛点 | 产品价值 |
|----------|----------|----------|----------|
| 学生 / 研究生 | 阅读论文、翻译英文材料、总结段落 | 频繁复制到网页翻译或 AI 网站，流程割裂 | 在任意阅读器中选中文本即可处理 |
| 科研 / 技术人员 | 快速解释术语、总结长段文献、理解代码片段 | 多模型切换麻烦，Prompt 重复输入 | 预设动作 + 指定模型，提高效率 |
| 办公用户 | 处理邮件、文档、网页内容 | 临时查询和改写需要切换软件 | 悬浮弹窗降低上下文切换成本 |
| AI 重度用户 | 自定义 Prompt、多厂商模型管理 | 不同 API Key 和模型分散 | 集中配置、统一入口调用 |

### 1.5 典型使用场景

| 场景 | 用户操作 | 系统行为 | 预期结果 |
|------|----------|----------|----------|
| 英文论文阅读 | 在 PDF 阅读器中选中一段英文 | 弹出划词菜单，点击「翻译」 | 展示中文翻译，可一键复制 |
| 长段文字理解 | 选中网页文章中的一段内容 | 点击「总结」 | 输出 3-5 条核心要点 |
| 专业术语查询 | 选中专业名词 | 点击「解释」或「查词」 | 给出通俗解释、英文释义、例句 |
| 临时输入查询 | 弹窗出现后修改输入框内容 | 点击任意动作重新提交 | 对修改后的文本执行 AI 操作 |
| 结果对照阅读 | 点击图钉固定弹窗 | 弹窗不自动关闭，可拖动 | 用户可边看原文边查看结果 |

### 1.6 产品边界

#### 需要支持

- Windows 10/11 桌面环境。
- 任意可复制文本的应用，包括浏览器、PDF 阅读器、Office/WPS、聊天软件、编辑器等。
- OpenAI 兼容接口的模型调用。
- 本地配置、本地历史记录、本地加密存储 API Key。
- 通过系统托盘常驻运行。

#### 暂不支持

- 移动端、浏览器插件版、macOS / Linux 版本。
- 对图片中的文字直接 OCR 识别。
- 完整文档级上传分析。
- 团队协作、云同步、多设备同步。
- 内置模型服务或代理服务器。

### 1.7 MVP 范围

MVP 版本优先保证「可稳定划词 → 可调用模型 → 可展示结果 → 可配置 API Key」这条核心链路。

| 优先级 | 功能范围 | 说明 |
|--------|----------|------|
| P0 必做 | 模型管理、默认模型、测试连接、API Key 加密存储 | 没有这些无法使用 |
| P0 必做 | 划词检测、悬浮弹窗、翻译/总结/解释/查词 | 产品核心体验 |
| P0 必做 | 流式输出、复制结果、错误提示、系统托盘 | 基础可用性 |
| P1 应做 | 自定义动作、动作排序、快捷键、历史记录 | 提升实用性 |
| P1 应做 | 弹窗外观设置、动画、主题、首次引导 | 提升完整度 |
| P2 可后置 | 结果钉住、随打随搜、剪贴板监听、面板拖拽 | 增强体验 |
| P2 可后置 | 导入导出设置、检查更新、多语言界面 | 后续迭代 |

## 二、功能模块

### 模块一：AI 模型管理

**入口：** 主窗口 → 模型管理标签页

#### 2.1.1 功能概述

管理 AI 厂商的 API Key 及可用模型，支持国内外主流大模型平台。

#### 2.1.2 预设厂商

| 厂商 | 默认 Base URL | 说明 |
|------|-------------|------|
| OpenAI | `https://api.openai.com/v1` | 国外主流 |
| DeepSeek | `https://api.deepseek.com/v1` | 国产高性价比 |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 阿里云 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | 清华智谱 |
| 自定义 | 用户自行填写 | 兼容 OpenAI 接口的任意服务 |

#### 2.1.3 功能清单

| 编号 | 功能 | 说明 |
|------|------|------|
| M-01 | 添加厂商 | 选择厂商类型，填入 API Key，可选修改 Base URL |
| M-02 | 自动拉取模型列表 | 填入有效 API Key 后，自动调用 `/models` 接口拉取模型列表 |
| M-03 | 模型列表展示 | 每个模型显示名称、状态开关、思考模型标记 |
| M-04 | 思考模型标记 | 用户可为每个模型手动标记/取消「思考模型」标签（如 DeepSeek-R1、o1 系列） |
| M-05 | 模型启用/禁用 | 独立开关，控制该模型是否在划词弹窗中可选 |
| M-06 | 设置默认模型 | 指定一个默认模型，划词操作未特别指定时使用此模型 |
| M-07 | 测试连接 | 一键调用 API 验证 Key 是否有效 |
| M-08 | Key 安全存储 | API Key 使用系统级加密存储（electron-store + safeStorage），界面显示为掩码 |
| M-09 | 删除厂商 | 删除厂商时同时清除其下所有模型配置 |
| M-10 | 查看/隐藏 Key | 点击眼睛图标切换 Key 的显示和隐藏 |

#### 2.1.4 界面结构

- 顶部：标题 + [添加厂商] 按钮
- 中间：厂商卡片列表，每张卡片包含：
  - 厂商名、API Key（掩码显示）、[测试] [查看/隐藏] 按钮
  - 模型表格：模型名 | 状态(启用/禁用/默认) | 思考模型标记
- 添加厂商弹窗：选择厂商 → 输入 Key → 可选修改 Base URL → 保存

### 模块二：划词动作管理

**入口：** 主窗口 → 动作管理标签页

#### 2.2.1 功能概述

管理选中文字后弹出的悬浮窗口中显示的操作按钮，包括预置动作和自定义动作。

#### 2.2.2 预置动作

| 动作 | 图标 | 默认 Prompt 行为 | 默认模型 |
|------|------|-----------------|----------|
| 翻译 | 🔤 | 将 {{selected_text}} 翻译为英文（可切换目标语言） | 跟随默认 |
| 总结 | 📝 | 用简洁的语言总结 {{selected_text}} 的核心要点 | 跟随默认 |
| 解释 | 💡 | 用通俗易懂的语言解释 {{selected_text}} 的含义 | 跟随默认 |
| 查词 | 📖 | 查询 {{selected_text}} 的释义、发音和例句 | 跟随默认 |

#### 2.2.3 功能清单

| 编号 | 功能 | 说明 |
|------|------|------|
| A-01 | 动作列表 | 显示所有动作，已启用在上、已禁用在下方 |
| A-02 | 启用/禁用 | 开关控制该动作是否出现在弹窗中 |
| A-03 | 拖拽排序 | 已启用的动作可拖拽调整弹窗中的显示顺序 |
| A-04 | 动作配置 | 每个动作可配置：目标语言/风格/受众等参数 |
| A-05 | 模型选择 | 每个动作可选择「跟随默认」或指定特定模型 |
| A-06 | 系统 Prompt 编辑 | 高级用户可自定义 System Prompt，支持 `{{selected_text}}` 变量 |
| A-07 | 动作测试 | 输入示例文字，实时预览动作效果 |
| A-08 | 添加自定义动作 | 自定义名称、图标、描述、System Prompt |
| A-09 | 删除动作 | 预置动作可禁用但不能删除，自定义动作可删除 |
| A-10 | 恢复默认 | 一键恢复所有动作到默认配置 |
| A-11 | 一键复制结果 | AI 返回结果面板内，每条结果旁有复制按钮，点击直接复制到剪贴板 |
| A-12 | 随打随搜模式 | 弹窗内提供输入框，用户可手动修改/输入要查询的文字再提交 |

#### 2.2.4 界面结构

- 顶部：标题 + [添加动作] 按钮
- 中部：已启用动作列表（可拖拽排序），每个动作项显示：
  - 拖拽手柄、图标、名称、核心配置项、[配置] [测试] 按钮
- 底部：已禁用动作列表
- 添加/编辑弹窗：名称、图标选择器、描述、System Prompt 编辑器、模型选择

## 三、技术架构

### 3.1 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|

### 3.4 数据流

```
用户选中文字
    ↓
主进程检测到文本选择（Polling / Hook）
    ↓
通过 IPC 发送选中文字到渲染进程
    ↓
悬浮弹窗渲染进程接收 → 读取动作列表和配置
    ↓
用户点击动作 → 读取对应的模型配置
    ↓
调用 AI API（通过主进程代理请求）
    ↓
流式返回结果 → 渲染进程展示
    ↓
结果写入历史记录（可选）
```


### 3.5 AI API 调用规范

#### 3.5.1 调用方式

- 统一使用 OpenAI Compatible Chat Completions 接口风格。
- 请求由主进程统一发起，渲染进程不得直接读取 API Key。
- 支持流式输出，优先使用 `stream: true`。
- 不同厂商的差异通过 Provider Adapter 层封装。

#### 3.5.2 请求参数

| 参数 | 来源 | 说明 |
|------|------|------|
| providerId | 模型配置 | 当前厂商 |
| baseUrl | 模型配置 | API 基础地址 |
| apiKey | 安全存储 | 仅主进程读取 |
| model | 模型配置 / 动作配置 | 优先使用动作指定模型，否则使用默认模型 |
| systemPrompt | 动作配置 | 动作的系统提示词 |
| selectedText | 划词输入 | 替换 `{{selected_text}}` 变量 |
| temperature | 动作配置 | 默认 0.3，可在高级配置中调整 |
| maxTokens | 动作配置 | 可选，避免返回过长 |
| stream | 固定默认 | 默认开启 |

#### 3.5.3 模型能力字段

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 模型 ID |
| displayName | string | 展示名称 |
| providerId | string | 所属厂商 |
| enabled | boolean | 是否启用 |
| isDefault | boolean | 是否默认模型 |
| isReasoning | boolean | 是否思考模型 |
| supportsStreaming | boolean | 是否支持流式输出 |
| contextWindow | number? | 上下文长度，可选 |
| maxOutputTokens | number? | 最大输出长度，可选 |

#### 3.5.4 返回处理

- 流式结果需要边接收边渲染。
- 用户点击取消时，中断当前请求。
- 请求失败时展示可理解的错误信息，并保留「重试」入口。
- 若厂商返回 Token 用量，则写入历史记录。

### 3.8 划词检测实现建议

划词检测是本项目技术风险最高的部分，建议采用「多策略兜底」方案。

| 策略 | 说明 | 优点 | 风险 |
|------|------|------|------|
| 鼠标抬起 + 剪贴板读取 | 检测鼠标拖拽结束后，尝试读取当前选中文本 | 实现简单，兼容面广 | 可能影响剪贴板，需要保护用户原剪贴板内容 |
| 全局快捷键触发 | 用户选中文字后按快捷键弹出菜单 | 稳定可靠 | 不如自动弹出顺滑 |
| 剪贴板监听 | 用户复制文字后触发弹窗 | 兼容性好 | 需要避免频繁误触发 |
| Windows UI Automation | 读取当前焦点控件的选中文本 | 更原生 | 实现复杂，不同软件兼容性不一 |

#### 推荐策略

- MVP 阶段：优先实现「快捷键触发 + 剪贴板监听」作为稳定方案。
- 迭代阶段：加入「鼠标抬起自动检测」。
- 高级阶段：探索 Windows UI Automation，提高自动划词体验。

#### 剪贴板保护要求

- 读取选中文本前缓存原剪贴板内容。
- 读取完成后尽量恢复原剪贴板。
- 若恢复失败，需避免弹窗报错打断用户。
- 用户可关闭所有剪贴板相关触发方式。

## 四、非功能需求

### 4.1 安全

- API Key 使用 Windows 系统级加密存储
- 所有 AI API 请求通过主进程代理，渲染进程不直接持有 Key
- 不上传任何用户数据到第三方服务器

### 4.2 性能

- 悬浮弹窗弹出延迟 < 200ms
- AI 响应采用流式输出，首字延迟 < 2s
- 内存占用 < 200MB（常规使用）

### 4.3 兼容性

- 支持 Windows 10 及以上（64 位）
- 支持高 DPI 显示器


### 4.4 可用性

- 首次启动后 3 步内完成基本配置。
- 未配置模型时，弹窗应提示「请先配置模型」，并提供跳转入口。
- 常用动作默认启用，不要求用户手动创建。
- API 错误提示应翻译为用户可理解的中文文案。

### 4.5 稳定性

- 主窗口关闭后程序默认最小化到托盘，不直接退出。
- AI 请求失败不得导致程序崩溃。
- 任意配置文件损坏时，应自动备份损坏文件并恢复默认配置。
- 全局快捷键冲突时，应提示用户重新设置。

### 4.6 可维护性

- 主进程、渲染进程、服务层、类型定义分离。
- 所有厂商差异封装在 Provider Adapter 中。
- 所有配置项有默认值和版本迁移逻辑。
- 需求编号应在代码注释、任务管理和测试用例中保持一致。

### 4.7 隐私与合规

- 首次启用剪贴板监听或历史记录时，需要明确提示用户。
- 历史记录默认仅保存在本机。
- 导出设置时默认不导出明文 API Key；若用户选择导出 Key，需要二次确认。
- 黑名单程序中不得触发划词检测和剪贴板读取。

## 七、异常处理与提示文案

### 7.1 模型与 API 异常

| 异常场景 | 触发条件 | 用户提示 | 可执行操作 |
|----------|----------|----------|------------|
| 未配置 API Key | 用户首次使用或删除所有厂商 | 还没有配置 AI 模型，请先添加一个 API Key | [去配置] |
| API Key 无效 | 测试连接或请求返回认证失败 | API Key 似乎无效，请检查后重试 | [重新填写] [测试连接] |
| 模型不可用 | 指定模型被删除或禁用 | 当前动作使用的模型不可用，已切换为默认模型 | [知道了] [去设置] |
| 网络超时 | 请求超过设定时间 | 网络连接超时，可以稍后重试 | [重试] |
| 请求被限流 | API 返回 rate limit | 当前模型请求过于频繁，请稍后再试 | [切换模型] [重试] |
| 余额不足 | API 返回余额/额度不足 | 当前账号额度不足，请检查服务商后台 | [切换模型] |
| 返回为空 | AI 无有效输出 | 没有获得有效结果，请换个动作或模型试试 | [重试] |

### 7.2 划词与弹窗异常

| 异常场景 | 处理方式 |
|----------|----------|
| 选中文字过短 | 不弹窗，避免误触发 |
| 选中文字过长 | 提示文本过长，并提供截断后继续处理选项 |
| 当前程序在黑名单 | 不弹窗，不提示 |
| 弹窗超出屏幕边界 | 自动调整到屏幕内 |
| 用户连续选中不同文本 | 更新弹窗内容，并取消上一次未完成请求 |
| 用户点击外部区域 | 未钉住时关闭弹窗 |
| 用户按 Esc | 关闭弹窗，并取消当前输入焦点 |

### 7.3 建议统一提示风格

- 避免直接暴露英文错误栈。
- 错误提示格式：问题说明 + 可能原因 + 操作按钮。
- 严重错误可提供「复制错误信息」按钮，方便反馈。
- 所有失败状态都应允许用户重试或跳转到相关设置页。

## 八、验收标准

### 8.1 MVP 总体验收

| 编号 | 验收项 | 通过标准 |
|------|--------|----------|
| AC-01 | 首次启动 | 程序可正常安装、启动，并显示引导或主窗口 |
| AC-02 | 添加厂商 | 可添加至少一个 OpenAI 兼容厂商并保存 API Key |
| AC-03 | 测试连接 | 点击测试连接后能返回成功或明确失败原因 |
| AC-04 | 默认模型 | 用户可设置一个默认模型，后续动作默认使用 |
| AC-05 | 划词触发 | 在浏览器、PDF 阅读器、文本编辑器中至少有一种稳定触发方式 |
| AC-06 | 悬浮弹窗 | 选中文字后弹窗在 200ms 左右出现，不遮挡主要内容 |
| AC-07 | 执行动作 | 翻译、总结、解释、查词均可完成一次有效 AI 请求 |
| AC-08 | 流式结果 | AI 输出过程中界面逐步显示内容，不长时间空白 |
| AC-09 | 复制结果 | 点击复制后结果进入剪贴板，并显示已复制反馈 |
| AC-10 | 历史记录 | 开启历史后可查看本次操作记录 |
| AC-11 | 托盘运行 | 关闭主窗口后程序仍在托盘运行 |
| AC-12 | 安全退出 | 退出程序后无残留窗口和异常进程 |

## 十、开发任务拆分建议

### 10.1 里程碑拆分

| 里程碑 | 目标 | 主要任务 |
|--------|------|----------|
| M0 项目骨架 | 能启动 Electron + React 应用 | 初始化项目、窗口、路由、Tailwind、构建脚本 |
| M1 配置闭环 | 能配置模型并测试连接 | 安全存储、Provider 管理、模型拉取、测试连接 |
| M2 AI 请求闭环 | 能输入文本并返回 AI 结果 | Provider Adapter、流式请求、错误处理 |
| M3 弹窗闭环 | 能通过快捷键/划词唤起弹窗 | 悬浮窗口、位置计算、动作按钮、结果面板 |
| M4 动作系统 | 能自定义动作与 Prompt | 动作管理、排序、动作测试、变量替换 |
| M5 设置与历史 | 形成完整可用产品 | 设置页、历史记录、托盘、快捷键 |
| M6 打包发布 | 可安装、可升级、可反馈 | electron-builder、安装包、日志、版本信息 |

### 10.2 推荐开发顺序

1. 先做主窗口和配置管理，不急着做自动划词。
2. 先用手动输入框打通 AI 调用链路。
3. 再做悬浮弹窗和快捷键触发。
4. 最后做自动划词检测、剪贴板监听和高级交互。
5. 每个阶段都保留可运行版本，避免一次性堆功能导致难以排错。

## 十一、主要风险与应对方案

| 风险 | 影响 | 应对方案 |
|------|------|----------|
| 自动划词检测兼容性不足 | 核心体验受影响 | MVP 先提供快捷键/剪贴板触发，自动划词后续增强 |
| 剪贴板读取影响用户原内容 | 造成体验问题 | 缓存并恢复剪贴板，提供关闭选项 |
| 不同厂商 API 返回格式不一致 | 请求失败或解析失败 | 建立 Provider Adapter，统一内部数据结构 |
| 思考模型响应慢 | 用户误以为卡住 | 显示加载状态、流式输出、可取消请求 |
| API Key 泄露风险 | 严重安全问题 | 主进程独占 Key，safeStorage 加密，导出二次确认 |
| 弹窗抢焦点 | 干扰用户操作 | 默认不抢焦点，点击后再聚焦 |
| 高 DPI 定位不准 | 弹窗位置异常 | 使用屏幕缩放信息修正坐标 |
| 功能范围过大 | 开发周期失控 | 严格区分 P0/P1/P2，先完成 MVP |
